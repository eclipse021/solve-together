## 짧은 회고

### 준현

- 접근: N이 2억이 넘어 계속 이분탐색에서 고민하다, 일반 탐색도 실제 연산은 6천만번 정도로 줄어들어 일반 탐색으로 해결
- 막힌 지점: 2억이라는 숫자 때문에 이분탐색에서 계속 생각함,,,
- 다음에 기억할 것: while 문으로 계속 탐색하지 않고, len 길이 만으로 O(1) 번에 필요한 기지국 위치를 구할 수 있음
  -> 시뮬레이션 문제에서 while로 하나씩 돌려보는 습관이 있는듯,,, O(1)로 빠르게 계산 할 수 있을지 알아보고 적절한거 선택하자!

### 준희

- 접근: N이 최대 2억이라 아파트 전체를 탐색하면(`O(N)`) 안 된다고 판단하고, 최대 10,000개인 `stations`만 순회하는 방식(`O(M)`)으로 전환. 기지국 하나가 덮는 범위는 `2w+1`. 이미 덮인 곳 다음 위치(`current`)부터 다음 기지국의 왼쪽 끝 전까지를 빈 구간으로 보고, 그 길이를 커버 범위로 나눠 올림(`math.ceil`)해서 필요한 개수를 한 번에 구함. 마지막 기지국 뒤에 남은 구간도 같은 방식으로 처리.
- 막힌 지점:
  1. 마지막 남은 구간 길이를 구할 때 시작점까지 포함하려면 `n - current + 1`처럼 `+ 1`이 필요했음.
  2. 몫 연산(`//`)만 쓰면 나누어떨어지지 않을 때 남는 칸이 빠지고, 여기에 `+ 1`로 보정하면 딱 나누어떨어질 때 하나를 더 세게 됨. 두 경우를 모두 맞추려고 올림(`math.ceil`)을 적용.
- 다음에 기억할 것: 범위가 큰 문제는 전체를 시뮬레이션하지 말고 빈 구간 길이를 계산해서 한 번에 개수를 구하기. 구간 길이는 양 끝 포함 여부(`+ 1`)를, 개수는 올림 여부를 먼저 따져보기.
