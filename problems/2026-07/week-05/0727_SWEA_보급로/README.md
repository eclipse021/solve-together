## 짧은 회고

### 준현

- 접근: 처음에 BFS로 접근했는데 단순히 가깝다고 가중치가 작아지는게 아니고, 해당 칸의 깊이에 따라 가중치가 달라지므로 다익스트라로 접근함 (백준에 예전에 비슷한 문제 풀어본적 있는듯?)
- 막힌 지점:
  1) 0100 같은 입력을 그냥 int로 받음... -> 붙어있는 숫자 int로 안 받게 조심하자,,
  2) adj의 dist는 간선 비용이고 우선순위 큐의 dist는 시작점부터의 누적 거리라는 차이도 조심하기!
- 다음에 기억할 것:
  1) 숫자가 붙어 있는 입력은 char로 받기
  2) 다익스트라가 구현이 헷갈려 작은 그래프를 그려봤는데 확실히 잘 작성되는듯! 다음부터 기억이 안 나면 직접 그려보며 코드 작성해보자

### 준희

- 접근: 2차원 다익스트라는 처음이라 막막했는데, 처음에 BFS로 짜본 뒤 "deque → heapq로 바꾸고 누적 비용 비교 부분만 손보면 구조가 거의 그대로다"라는 걸 깨달음. 거리 테이블 초기화 → 시작점 push → pop 후 완화(더 작은 누적 비용이면 갱신 & push)라는 BFS와 동일한 뼈대.
- 막힌 지점: 딱히 크게 막힌 곳은 없었고, "BFS와 뭐가 다른가"만 잡으면 되는 문제였음. 가중치가 제각각이라 단순 BFS(먼저 도달 = 최소)로는 안 되고, 우선순위 큐로 "지금까지 누적 비용이 가장 작은 칸"부터 확정해야 한다는 점이 핵심.
- 다음에 기억할 것: 다익스트라 = BFS(deque)에서 heapq로 바꾼 것 + 누적 비용 완화 조건. 골격은 BFS와 같으니 겁먹을 것 없음. `if distance[r][c] < dist: continue`로 이미 확정된 칸 스킵, 목적지는 pop 시점에 return 가능. 힌트 없이 스스로 해결 → 다음에 다익스트라 나오면 풀 수 있을 듯.
