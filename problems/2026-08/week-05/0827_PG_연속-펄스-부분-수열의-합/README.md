## 짧은 회고

### 준현

- 접근: 인덱스를 오른쪽으로 이동하며 값을 갱신한다는 점에서 DP와 투 포인터 등을 생각했다. 최종적으로는 현재 값부터 새로 시작할지 기존 합에 더할지를 비교하는 방식으로 구현했다.
- 막힌 지점: 1, -1, 1 ...과 -1, 1, -1 ...인 경우를 각각 for 문으로 구했다. sequence 전체의 부호를 바꾸면 하나의 경우만 구해도 된다는 것을 나중에 알았다.
- 다음에 기억할 것: 없음.

### 준희

- 접근: 처음엔 모든 부분 수열을 다 보는 브루트포스를 떠올렸으나, N이 최대 500,000이라 `O(N^2)`는 시간 초과 확정 → 누적 합(prefix sum)으로 `O(N)`으로 줄임. 어떤 구간의 합은 누적 합 배열의 두 값 차이이므로, 정답 최대화는 누적 합 배열의 `max - min`으로 한 번에 구함.
- 막힌 지점: 부호가 정반대인 두 펄스 수열을 각각 계산해야 하나 고민. → 원래 누적 합에서는 뺄셈의 인덱스 순서(최솟값이 최댓값보다 앞)가 중요하지만, 이 문제는 서로 부호가 반대인 두 펄스가 존재해서, 인덱스가 뒤집혀 음수가 나와도 반대 부호 펄스를 곱하면 양수로 뒤집힘. 결국 펄스 하나만 적용한 누적 합에서 `max - min`이면 두 경우가 한 번에 커버됨.
- 다음에 기억할 것: 연속 구간 합 최대화는 누적 합 배열의 `max - min`. 부호가 대칭인 문제는 한쪽만 계산해도 반대 경우가 함께 처리된다.
