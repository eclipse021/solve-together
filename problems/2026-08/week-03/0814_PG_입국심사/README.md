## 짧은 회고

### 준현

- 접근: 특정 시간 동안 처리 가능한 인원을 계산하는 이분 탐색으로 해결 (해당 특정 시간 접근을 이분 탐색)
- 막힌 지점: int 에서 Long으로 자동으로 형변환 되지 않아 (long) 형변환이 필요했음
- 다음에 기억할 것:
  - 10억 * 10억을 막상 log2N 해보면 60정도밖에 안 된다,,, 생각보다 큰 수도 이분 탐색이 가능하다!
  - int → long은 자동 변환되지만 int → Long은 (long) 명시적으로 변환 필요함
  - 이분 탐색은 while (start <= end)에서 조건을 만족하면 answer = mid; end = mid - 1, 실패하면 start = mid + 1로 구현하면 간결함.

### 준희

- 접근: "정답(=총 소요 시간) 자체를 이분탐색". `mid`시간이 주어졌을 때 각 심사관이 `mid // time`명씩 처리하므로 전체 처리 인원 = `sum(mid//t for t in times)`. 이게 `n` 이상이면 `mid`를 줄이고(`right=mid-1`), 모자라면 늘려서(`left=mid+1`) 조건을 만족하는 최소 시간을 찾음. 범위는 `1 ~ max(times)*n`.
- 막힌 지점:
  1. 처음엔 "가장 빨리 비는 심사관"을 계속 뽑는 우선순위큐를 떠올렸는데, 문제 분류가 이분탐색이라 의아. → 인원(n)이 너무 커서 시뮬레이션은 범위가 넓어 터진다는 걸 깨닫고 "시간을 이분탐색" 방향으로 전환.
  2. "이 `mid` 시간에 몇 명이나 심사 가능?" 로직에서 오래 고민 → 각 심사관이 독립적으로 `mid//time`명 처리하니 그냥 다 더하면 된다로 정리.
- 다음에 기억할 것: 답의 범위가 매우 넓고 "특정 값에서 조건 만족 여부"를 O(N)에 판정할 수 있으면 값 자체를 이분탐색(parametric search). "그 시간에 처리량"은 심사관별 `mid//time` 합.
