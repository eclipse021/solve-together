## 짧은 회고

### 준현

- 접근: 스택에 중단된 작업을 저장해 두고 최근에 저장해둔 작업을 스택에서 빼서 실행하는 방식으로 구현
- 막힌 지점: 
  - 시간에 따라(1분 간격)으로 시뮬레이션을 돌렸는데, 처음에는 하루 24시간(1500분 이하)로 반복문을 잡았더니 틀림
    - 하나의 작업이 진행중이면 다른 작업은 멈춰야 하므로 하나당 (최대 작업시간 100분) * (최대 작업 개수 1500개) = 1,500,000으로 범위를 조정
  - 스택 내부 원소를 변경하는 것은 허용 안 됨 주의
- 다음에 기억할 것:
  - `시간`으로 시뮬레이션 돌릴 때는 시간 범위(중단된 시간 등) 잡는 거에 주의하자!

### 준희

- 접근: 시작 시각으로 정렬 후 순회. 현재 과제를 다음 과제 시작 전까지 끝낼 수 있으면 바로 완료 처리하고, 남는 여유 시간 동안 스택 top(가장 최근 중단 과제)부터 꺼내 이어서 진행. 못 끝내면 남은 시간만 스택에 push. 마지막 과제 뒤엔 스택을 전부 pop(LIFO 순).
- 막힌 지점 (2가지에서 난항):
  1. 여유 시간에 기존 과제 꺼내오기: 현재 과제를 끝내고 다음 시작까지 시간이 남으면, 그 시간으로 스택에 멈춰둔 과제를 이어 처리해야 한다는 흐름을 잡는 데 오래 걸림. 여유가 남는 한 스택을 계속 pop하되, top의 남은시간이 여유보다 크면 그만큼만 깎고 멈춤.
  2. 스택엔 시작시간을 버린다: 중단된 과제는 다시 시작할 때의 시각이 중요한 게 아니라 남은 소요시간만 있으면 됨. 그래서 스택엔 `[이름, 남은시간]`만 저장(시작시각은 폐기)한다는 아이디어에서 막힘.
- 다음에 기억할 것: LIFO로 "중단→재개"되는 작업은 스택. 저장할 때 필요한 정보만 남기기(재개엔 시작시각 X, 남은시간 O). 여유 시간을 스택 처리에 흘려보내는 그리디.
