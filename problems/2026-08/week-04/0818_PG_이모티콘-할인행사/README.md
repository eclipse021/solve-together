## 짧은 회고

### 준현

- 접근: DFS로 각 이모티콘 할인율을 순열로 완전 탐색함
- 막힌 지점: 배열 상태를 다음 DFS로 넘길 때 원본이 같이 바뀌는 걸 피하기 위해 깊은 복사하는 Java 문법을 찾아봄
- 다음에 기억할 것:
  - `int[]` 복사는 `arr.clone()`으로 간단하게 독립 배열을 만들 수 있음.
  - Java에서는 `resultList`, `totalSignup` 처럼 카멜 케이스로 작성하자!

### 준희

- 접근: 할인율은 `{10,20,30,40}` 4가지뿐이라 이모티콘 개수만큼 `product`로 모든 조합을 완전탐색(브루트포스). 각 조합마다 유저별로 "할인율이 기준 이상인 이모티콘"을 사서 총액을 계산하고, 그 총액이 유저의 플러스 가입 문턱(`users[i][1]`) 이상이면 가입자 +1, 아니면 그 금액을 매출에 더함. (가입 우선 → 동률이면 매출 큰 것) 기준으로 최댓값 갱신.
- 막힌 지점:
  1. 처음엔 "유저마다 모든 조합의 결과를 저장해두고 나중에 정렬해서 뽑는 건가?" 했는데, 그럴 필요 없이 조합을 도는 그 자리에서 집계하고 바로 max 갱신하면 됐음.
  2. `temp_plus`/`temp_money`/`user_cost` 같은 임시 변수가 많아 어느 루프 스코프에 둘지(조합 단위 vs 유저 단위) 배치를 고민.
- 다음에 기억할 것: 완전탐색은 후보를 다 저장해 정렬하지 말고, 순회하며 즉석 비교(max 갱신)하면 메모리·코드가 간결. 임시 변수는 "언제 리셋돼야 하나"로 스코프를 정한다(조합마다 vs 유저마다).
