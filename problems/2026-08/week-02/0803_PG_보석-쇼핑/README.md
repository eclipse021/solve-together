## 짧은 회고

### 준현

- 접근: dp 방식으로 해당 인덱스에서 시작할 때 최소 구간을 정하는 방식으로 dp 배열을 채우려고 했음
- 막힌 지점: dp_index, diff_index 양쪽 index 범위를 생각해야 했고 맨 처음에 index 시작과 끝 처리 부분에서 에러가 남
- 다음에 기억할 것:
  - 투 포인터는 양 끝에서 범위를 좁히는 방식뿐만 아니라, 두 포인터가 같은 지점에서 시작해 같은 방향으로 이동하며 구간을 탐색하는 방식도 있다!

### 준희

- 접근: 두 포인터가 같은 방향으로 이동하는 슬라이딩 윈도우. `start`를 밀며 모든 종류를 담을 때까지 `end`를 확장하고, 조건을 만족하는 순간의 구간 길이를 최소값과 비교.
- 막힌 지점: 투포인터 로직 자체는 금방 세웠는데, 구간이 모든 종류를 담았는지 매번 `set`으로 검증해서 시간초과. → 구간 내 보석별 개수를 딕셔너리로 유지해 `len(gem_dict) == 전체 종류 수`로 O(1) 판정하도록 고침. `start`가 빠질 때 카운트를 `-=1` 하고 0이면 `del`.
- 다음에 기억할 것: 슬라이딩 윈도우에서 "조건 만족 여부"를 매번 전체 재계산하면 O(N²)로 터진다. 윈도우 상태(개수 dict)를 증분 갱신하면 O(N). 종류 수 판정은 dict 키 개수로.
