### 준희

- 접근: 요청 시각으로 정렬 → 인덱스 `i`로 "현재 시각까지 도착한 작업"만 힙에 push, 힙에서 소요시간 최소(SJF)를 꺼내 처리하며 `now_time`을 작업 끝나는 시점으로 점프. 힙이 비면 다음 작업 요청 시각으로 워프.
- 막힌 지점 (4가지 헷갈림):
  1. 시간 흐름: 1ms씩 `+=1` 돌리면 범위 커질 때 비효율 → 쉬지 않고 일하면 `now_time += job_time`으로 끝나는 시점까지 단번에 점프.
  2. 힙 채우기: 매번 `jobs` 전체를 for로 스캔하면 낭비 → 정렬 후 `while jobs[i][0] <= now_time`로 도착분만 넣고 `i` 증가.
  3. 디스크가 노는 타이밍: `while q`만 짜면 힙이 비는 순간 루프가 끝나버림 → 아직 남았는데(`i < len`) 힙이 비면 `now_time = jobs[i][0]`로 타임워프.
  4. 첫 작업 하드코딩의 함정: 첫 작업을 수동으로 넣고 `i=1`로 시작하면 (a) 첫 요청이 0ms가 아닐 때 시간이 꼬이고 (b) 동시 도착 시 우선순위 정렬이 무의미해짐 → 빈 힙(`i=0`)으로 시작해 3번의 워프 로직이 자연스럽게 초기 케이스까지 처리.
- 다음에 기억할 것: 이벤트 기준으로 시간을 점프시키는 스케줄링 패턴. 초기값을 특수 처리(하드코딩)하지 말고 루프의 일반 로직이 첫 스텝도 자연히 커버하게 짜면 예외가 사라진다.
