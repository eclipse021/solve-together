## 짧은 회고

### 준현

- 접근: 배열 크기가 2억이므로 O(N)으로도 시간초과 이므로, O(logN) 에서 풀이법을 고민하다 이분탐색으로 해결
- 막힌 지점: x
- 다음에 기억할 것: 인덱스를 원소로 이분탐색할 때 mid가 1일 때 예외처리 주의하자

### 준희

- 접근: stones 원소 값이 최대 2억이라 순차 시뮬레이션(`O(N)`)은 시간 초과 확정. "조건을 만족하는 최대 인원수"를 구하는데 인원수가 정해지면 건널 수 있다/없다가 명확히 갈리므로 매개변수 탐색(이분 탐색)을 떠올림. 탐색 범위 1~2억을 절반씩 줄여 `O(log N)`으로 압축.
- 막힌 지점:
  1. 결정 함수(mid명이 건널 수 있는가) 구현이 살짝 막막해 `skip` 변수 힌트를 참고. → 돌 내구도가 mid보다 작으면 밟을 수 없어 `skip += 1`, 밟을 수 있으면 `skip = 0`으로 초기화, `skip`이 k에 도달하면 건널 수 없으므로 False. 연속된 빈 공간을 카운팅하는 깔끔한 로직.
  2. 처음에 루프 끝난 뒤 `mid`를 그대로 반환하는 실수. → 이분 탐색은 종료 시 mid가 정답을 보장하지 않으므로, 건널 수 있을 때(`is_cross`)의 mid를 `answer`에 따로 저장하며 탐색을 이어가야 함.
- 다음에 기억할 것: 입력 스케일이 크면(수억) 시뮬레이션 버리고 이분 탐색부터 의심. 매개변수 탐색의 결정 함수는 `skip`처럼 연속 제약을 카운팅하는 방식으로 설계. 정답은 조건 만족 시점의 mid를 별도 변수에 저장.
